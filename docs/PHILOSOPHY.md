# SHUNYA Philosophy

## 1. Problems before technologies

Technologies change faster than engineering problems.

## 2. Reason before prescribing

A solution without diagnosis is a guess.

## 3. Preserve trade-offs

Every useful engineering pattern solves one problem while changing another.

## 4. Evidence over authority

Prefer measurements, experiments, incidents, and reproducible examples over "this is the best practice."

## 5. Patterns should travel

A good pattern should survive a technology change.

## 6. Humans and agents use the same knowledge differently

Humans browse and reason.

Agents retrieve and compose.

The underlying engineering knowledge should support both.

## 7. Small entries beat giant documents

Each entry should solve one conceptual problem well.

## 8. SHUNYA is not an oracle

Multiple solutions may be valid.

The repository should expose the reasoning and trade-offs so the engineer or agent can make the final decision.
