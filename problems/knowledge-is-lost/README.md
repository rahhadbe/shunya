# Knowledge Is Lost

Use this family when important constraints, decisions, or operational history disappear as people, systems, or projects change.

## What engineers notice

- a team repeats a previously settled investigation
- a change breaks an undocumented constraint
- maintaining a system depends on a single person remembering its history

## Questions to ask first

1. What knowledge is repeatedly needed, and when is it needed?
2. What evidence would let a new engineer understand the original decision?
3. Where should this knowledge live so it remains discoverable and reviewable?
